# Frontier Orchestrator project guidance

Read `PROJECT_MEMORY.md` before answering project questions or changing code when that local file is present. It is intentionally ignored by Git; contributors can use `docs/MVP.md` as the public handoff. Keep confirmed facts, proposals, and unknowns distinct. Update local memory when the user makes a durable decision or an integration is verified. Never record credentials.

The product goal is a frontier-led delegation loop: the frontier model plans, assigns bounded work to a local model, receives evidence, and reviews or requests revisions. The coordinator owns task state, plan versions, limits, permissions, and the event log.

Build the smallest complete coding workflow before adding more models or parallel workers. Keep the code workspace and tool execution location explicit. Do not treat text generated by a model as authorization to execute arbitrary commands or expose files to a cloud provider.

The separate `Local LLM` project documents DeepSeek deployment and tuning. Do not change its runtime configuration as part of this application's implementation unless the user specifically asks.
