# Mosaic terminal beta implementation plan

Owner approved the plan in chat and explicitly chose direct Codex implementation without Mosaic dispatch. Build in this isolated worktree from fa95be6. This document is the approved requirements and implementation brief.

## Global constraints

Private downloadable Apple Silicon Mac beta. Guided installer and Hermes-inspired compact terminal observer. Codex host and reviewer with a selectable OpenAI-compatible Chat Completions worker, local or hosted (including existing Spark endpoints). No desktop app or browser dashboard in the beta package. One API worker configured at a time. Existing four workflow policies remain supported. Research stays parked. No runtime changes on the Sparks. Existing personal Mosaic installation, processes, history and bindings must be preserved. Do not publish. Do not read or expose cloud authentication files or secret values. Live provider calls require explicit concrete bounded authorization; prepare the runnable smoke path but report absent live evidence honestly.

## Task 1: Implement the complete beta entry path

Deliver a coherent working path from archive installation through guided setup to authenticated MCP dispatch and a live terminal observer. Use existing coordinator APIs and protected checks, and existing versioned package integrity patterns. Keep code readable, small focused modules, no unrelated rewrites. Add meaningful tests before implementations. Commit the implementation and provide a report with exact red/green and suite results.

### Installer and packaging

Build a standalone versioned tar.gz archive plus SHA256. Bundle pinned Node 24 for Darwin arm64 and production runtime dependencies. Target machine needs no npm or Homebrew. Package builder accepts an explicit Node executable for offline tests and verifies version/platform/architecture for real packaging; release builder must include dependency licenses. ./install installs for current user into ~/Library/Application Support/Mosaic Beta/versions with private state/config separate. Place executable launcher ~/.local/bin/mosaic, refusing to overwrite a foreign entry. Check platform/architecture and explain failures. Guided PATH handling supports default macOS zsh without overriding unrelated shell configuration; show exact change before applying a managed block. Preserve spaces in paths. Re-running install is idempotent, tampered files fail verification, failed update restores prior beta launcher. Existing live beta work prevents unsafe restart/update. Distinct LaunchAgent and MCP name mosaic-beta, dynamic loopback port, no collision with installed Mosaic. No automatic modification of old Mosaic. Implement uninstall scoped to owned unchanged beta bindings retaining state/evidence and give a help command. Verify package directly contains no desktop/browser assets; server headless option avoids attempting to read excluded UI assets. Do not blindly copy all src plus all research files into beta artifact. Include only runtime dependency closure needed for coding or isolate parked imports safely.

### Commands and setup

mosaic opens setup if incomplete, otherwise observer. mosaic setup revisits configuration. mosaic doctor checks installation, coordinator, Codex executable/sign-in/MCP, configured worker with actionable errors. mosaic mcp exposes authenticated bridge with clean stdout. Setup discovers Codex and checks login using supported CLI, offers Codex only or Codex + API worker; display name, base URL, optional bearer key (masked input), discovery/manual model selection. Completed responses default; allow explicit streaming. Missing /models should allow manual model ID. Setup previews exact additions before writing user MCP settings. Install distinct beta skill/instructions that direct explicit Mosaic Beta prompts to mosaic-beta tools and correct runtime; do not replace existing personal skills or instruction blocks. Supply usable starter prompt. Offer one explicit optional fixed-prompt connection test containing no repo data and bounded time/output. Connection success does not imply coding-model qualification. No secret values in stdout/logs/event records or shell arguments. Save private config atomically with mode 0600, directories 0700. On reconfiguration reject active or prepared incompatible work rather than relabeling in-flight work. Setup must work on clean machine lacking Codex by showing installation/sign-in next steps and resuming later.

### API worker integration

Reuse HTTP adapter, add optional bearer auth to streaming and completed calls, model discovery + explicit/manual selection behavior. Keep existing adapter callers unchanged. Respect deadlines, request accounting, body bounds and no silent response retry or fallback. Generalize display labels away from DeepSeek while keeping legacy actor enum/policies compatible. New beta goals bind nonsecret worker profile identity (endpoint/model/display name/config revision) into approved manifest/hash. Activation and every dispatch verify binding against current profile; prepared goals cannot silently pick up changed provider settings. Historical attribution comes from saved goal/request profile, never current global config. Secrets never enter approved manifests. Legacy goal hashes and existing unbound callers remain compatible. Selected model need not be branded DeepSeek. Keep Codex-only path functional with no worker configured. Native progress and actual API captures remain distinct.

### Terminal observer

Use Node terminal APIs (ANSI/readline), no full framework necessary. Compact charcoal/default terminal background, cyan accent, restrained green/amber/red statuses with text equivalents. Current goal header, agent assignment rows, scrolling chronological handoff feed and footer. Select current active goal or most recent saved goal; add goal picker for multiple jobs. Rows include configured display name, role, assignment, status, last updated. Support Codex + worker simultaneously only when real records indicate overlap. Reviewer waiting on checks shows waiting. Show captured vs reported evidence honestly, idle/disconnected/unknown states accurately. q and Ctrl-C close observer only, restoring cursor/terminal. Up/down selects rows, Enter details, Esc back. Bounded details use observer_evidence. Approvals stay in Codex with actionable guidance. Narrow terminals stack layout. Non-TTY/NO_COLOR produces plain text with --once status option. Terminal text strips control sequences from model/task data. Use authenticated viewer connection only, existing observer_snapshot/timeline APIs. Poll about once per second, durable cursor and de-duplication, capped local feed. Reopen shows recent saved events, not only future events. Handle service restart, connection rewrite, reconnect without resubmission. Bound network requests and payloads; show last observed state as stale when disconnected. Avoid raw provider token output on default feed.

### Tests and delivery

Run focused new tests and full npm test once after implementation. Record existing failures individually. Exercise auth/manual model lookup, response formats, changed approved binding, old hashes, no-secret failures, late stream error, viewer-only capabilities, concurrent actor records, review waiting/failing checks, reconnect/dedup, TTY cleanup, nonTTY, narrow layout. Installer fixture tests cover fresh isolated home, repeated install, foreign launcher/config, integrity tamper, failure rollback, separate registration, missing Codex and interrupted setup. Do not write real global user settings for tests. Build actual archive, install into an isolated fixture location and smoke packaged --help/doctor/status/MCP routes. Provide README for beta only with exact commands and honest validation gaps. Main controller will verify archive and review independently. Clean separate macOS account/VM, real Spark task, real hosted provider task and real Codex review remain explicit delivery gates; do not label fixture tests as these.
