# Offline research review lifecycle

The approved offline implementation adds policy3/research@4/catalog2 for explicitly opted-in collaborative research. Absent policy, policy1, policy2 and deterministic operator research retain their previous contracts. Historical reports and allowances are not migrated. DeepSeek-only, Codex-only and overnight modes cannot opt into this contract.

A malformed report now retains a separate bounded repair proposal with individually provenance-valid claim records, immutable operation/result/offer hashes, whole-report errors and rejected-claim errors. It is untrusted writer context. It cannot become a canonical candidate or grant acceptance.

A fully valid, complete report becomes an immutable candidate at `awaiting_semantic_review`. It binds the manifest, canonical report, source snapshot, offered catalog, reserved model request/result and approved rubric. DeepSeek must be observed quiescent before the coordinator presents the candidate in its review inbox. The saved `proposal.json` is available through existing artifact tools.

`research_review` is a mutating, closed reserve/submit union. Reserve takes taskId, candidateHash, rubricHash and idempotencyKey; it spends a native reviewer reservation before any operator dispatch. Submit adds ticketId, decision (accept/revise/reject), findings and coverage. Findings use unit/code/message/evidence. Evidence is optional and must be a selector actually offered to that candidate. Acceptance requires every descriptor unit exactly once and no findings. The tool launches no inference; the trusted operator must independently review the packet. Native reservations count separately from DeepSeek model/search/download operations and against existing goal/task reviewer limits.

One revision returns the same job to correction, with at most two model calls and no new retrieval. Initial generation stops before consuming those two calls; all calls remain within the existing 20-call ceiling. A narrower model limit can leave insufficient generation capacity and produces an unaccepted result. The whole replacement needs the second independent review. Rejection, exhaustion and expiry preserve evidence and produce partial/unaccepted output. No model prose follows acceptance.

Accepted policy3 claims.json and sources.json use the exact immutable canonical UTF-8 bytes, so terminal artifact byte hashes equal the descriptor hashes without Python/JavaScript number reserialization. Both collection and readiness verify these report and source bindings. Legacy artifact formatting stays unchanged.

A timely acceptance commits a local finalization intent. Restart can replay cached model results even at the last allowed generation/correction call or that intent without new inference; it cannot refresh identities, deadlines or counters. A failed artifact write may be explicitly resumed after the deadline only for the already committed local intent and known quiescent ownership. Stop and ambiguous execution block review/correction. Generic task_review, question answers, model flags and progress reports cannot accept policy3 research.

Policy3 readiness additionally requires a bound pre-final acceptance receipt and a separate independent live assessment for the exact final report/source artifacts. Policy2 readiness remains compatible. Fixture results never satisfy the live gate. Checksums prove binding and integrity; they do not prove reviewer independence, semantic truth or release acceptance.

The 16 approved regression cases are mapped in REGRESSION_COVERAGE.json. Simulated verdicts establish mechanical behavior only. Native Codex-host discovery, real-model usefulness/entailment, live search/page behavior, deployment, installation, coding and physical phone acceptance remain outside these offline tests.

## Local approval authority (internal version 1)

Policy3 acceptance now comes from durable coordinator state. A remote receipt with consistent hashes is corroborating evidence. It cannot authorize a local decision. Same-user arbitrary modification of the trusted database/code remains outside this boundary; native role labels are not authentication.

Before reserve dispatch, the existing `research-intent-<key>` command records the native reviewer reservation and exact descriptor/job/manifest. The bounded returned ticket in `task.researchReviewTickets` records version, goal/task/job/manifest, frozen descriptor, nativeReservationId, reservationKey and reservedAt. Reserve acknowledgments must have a nonempty bounded ticket ID, exact candidate/rubric and boolean dispatchRequired. Ownership, current candidate and the still-reserved native row are checked again before the local ticket is saved. Duplicate backend ticket IDs fail closed.

Before submit RPC, `research-submit-intent-<key>` atomically saves the ticket's `submissionIntent`: version 1, pending state, goalId/taskId/jobId/manifestHash, exact descriptor, ticketId/nativeReservationId, submissionKey, complete input, inputHash and intentAt. `inputHash` is the Node canonical digest of `{input,key}`; the checksum never substitutes for the saved input. Inputs remain limited to 32 KiB. Descriptors contain hashes/units, not repeated source bodies. Accept requires unique complete coverage and empty findings locally as well as remotely.

A submit acknowledgment must exactly equal the requested job/ticket/candidate/decision and queued status. Before the original deadline, one SQLite transaction changes submissionIntent to acknowledged, stores the acknowledgment and timestamp, completes the matching native reviewer row with ticket/decision/candidate/submissionHash, saves the frozen `task.researchReviewAcceptance` (same record with accepted state), and queues the task. A revise/reject never creates this accepted record. Later current proposals and remote receipts cannot overwrite it. Acknowledgment/ownership mismatch leaves the reservation spent and local acceptance absent.

Collection validates the full remote descriptor against this accepted record, including report/source/offers, manifest/job/rubric, raw request/result lineage and every unit. It requires the real local ticket and completed native reviewer row with exact goal/task and submission hash. The returned ticket key, binding, full submission and result must match the local operation. Actual report/source byte hashes must equal the locally accepted descriptor. `Coordinator.completeTask` independently requires this durable authority and exact result binding. Policy3 partial completion is atomically partial, including its event; it never emits an accepted transition first.

The read-only standalone readiness checker has no trusted coordinator database/reviewer rows. It still rejects invalid remote evidence, timing and artifact bytes, but an otherwise valid policy3 receipt remains pending with `authoritative_local_acceptance_required`. It does not synthesize local authority from imported receipt JSON. Policy2 readiness remains compatible.

## Recovery limits

The existing effect/command journals replay the same key and input, reject conflicts, and retain ambiguous native reservations. Lost reserve/submit replies replay the same backend operation without another native reservation. Actual SIGKILL fixtures cover before reservation, before/after submit intent, after remote save, after acknowledgment/before atomic commit, after acceptance commit, before/after collected bytes and after completion. A killed collection owner becomes uncertain under the coordinator lease; reconciliation verifies exact remote identity and known quiescence before collection resumes. Accepted terminal replay adds no work or accepted event.

This repair deliberately does not migrate pre-repair policy3 records or support new approval after expiry. Missing local authority remains unaccepted. A pending submission may replay only while the existing live goal/task boundary permits it; no broad late-acknowledgment exception was added. Already committed effect results replay without RPC. Deadlines, IDs, historical artifacts and spent counters never reset. Stop/pause/uncertain ownership cannot create a fresh submission. Do not restore an old database to reset spending or silently downgrade active state containing these records.

The additional 24-case repair matrix is in `LOCAL_ACCEPTANCE_REGRESSION_COVERAGE.json`. Fixture decisions verify mechanics and byte integrity, not semantic truth, independent reviewer authenticity or actual Codex-host mutation permissions.

## Return-review restart and readiness followup

`checkpoint.remotePaused` is a saved contact cursor, not authority to resume the backend. The adapter observes and verifies the actual job/manifest identity, spending and quiescence first. Only eligible suspended/stopped/blocked/failed states may resume within the original live task boundary; completed/partial output goes through the existing collection checks without resume. A resume rejection followed by verified quiescent terminal state is collected through those same checks. Uncertain execution and local pause/stop remain unaccepted. The cursor is cleared durably after verified quiescent reconciliation, without replacing the accepted descriptor, identities, deadlines or accounting.

`harness-research-restart.test.mjs` persists the cursor using actual pause/resume controls and the real Python store, closes the coordinator, finalizes while it is unavailable, and exercises both queued restart and uncertain reconciliation. It checks exact local authority, reviewer rows, feedback, IDs, deadlines, counters and single acceptance, plus lifecycle/control/identity/race boundaries. The CLI/SDK package fixture separately injects only the stale nonauthoritative cursor while stopped; its approval is created through real review operations, and manual pause remains effective until explicit resume.

A current, bound failed independent assessment stays failed in both the quality gate and pre-promotion result, including when policy3 lacks a receipt or trusted local approval. Receipt integrity checks still apply when evidence is supplied. Otherwise passed/pending policy3 evidence remains pending without authoritative local acceptance. Policy2 behavior is unchanged. These fixtures prove mechanics, not live semantic quality or installation readiness.

## Source review resolution

The single independent source review found three additional binding gaps. Proposal descriptors now require the exact supported version1 fields, bounded hash/request references, matching offered-catalog lineage and a unique exact unit list derived from the canonical report's claims and section entries. The report bytes are parsed to enumerate units, never reserialized for acceptance. Reserve acknowledgments are a closed four-field wire object; extra source bodies and coordinator-owned fields cannot enter a local ticket. Completed status/export/collection and receipt envelopes must match the local job/manifest/mode and original deadline; the expected Python deadline is `floor(local milliseconds / 1000)`, matching the reserved manifest's `not_after`. Receipt status must be completed, and finalization must precede that original deadline. These checks preserve the approved report format and semantic rubric.
