## Original first live milestone — October 2026

The original milestone was a **text-only** Mac terminal design handoff:

1. The user supplies a substantial project-design brief.
2. Codex proposes one focused assignment and short plan; the user accepts the exact plan before dispatch.
3. DeepSeek answers through an already-running OpenAI-compatible API.
4. Codex reviews the answer and accepts, reports a blocker or requests one focused revision.
5. The terminal displays the answer, review, final status and job ID; the JSONL event log retains the same handoffs.

This path gives the model no application tool for editing files or running commands. It allows at most two local answers and preserves approval/results when a provider fails. “Reviewed” means assessed against the brief, not independently fact-checked in every detail. A distributed service spanning two Sparks is one endpoint, not two independent workers.

The offline foundation remains [`src/demo.mjs`](../src/demo.mjs), [`src/coordinator.mjs`](../src/coordinator.mjs), the [fake adapters](../src/adapters/fake.mjs) and JSONL store. Every model response in the original demo is fake. It automatically approves its fake plan, records a revision and finishes without model calls, task file edits or coding checks. Contributors can run it without credentials or special hardware using the README commands.

The separate [`src/live.mjs`](../src/live.mjs) terminal path uses real adapters unless `--fake` is selected. A real brief goes to the signed-in Codex CLI for planning/review, and the assignment/revision goes to the configured worker API. That path needs deliberately configured credentials/endpoints and a brief authorized for those providers; the source smoke does not invoke it.

## Preserved overnight contract and explicit exceptions

The [legacy overnight workflow](OVERNIGHT.md) grew from that handoff into sequential coding stages in an isolated Mac worktree. DeepSeek drafts the plan and implements; automatic Codex use is review after protected checks pass. Defaults are five attempts and at most two reviews per stage, an eight-hour deadline and a thirty-minute reconnect window. One optional pre-stage guidance call requires explicit request. Codex does not write routine assignments, edit code or rescue exhausted stages in this mode. Further attempts or expanded scope need the supported approval/recovery path.

The later [four-mode coding core](MOSAIC_CODING_CORE.md) explicitly permits native Codex implementation in collaborative and Codex-only goals. DeepSeek-only excludes Codex implementation, review and fallback. These are scoped exceptions selected for a goal; they do not erase the historical overnight restriction or reset spending and ownership. Research remains parked.

The [portable beta guide](TERMINAL_BETA.md) describes a separate coordinator/bridge and local package path. App selection, model discovery, inference, actual host connection and reviewed coding results are different evidence states. Pull-based host review can remain durably waiting while its conversation is inactive; there is no automatic wakeup promise.
