# Scoped memory and protected learning

Use `memory_retrieve` with goal/query/capability for at most four applicable
lessons/8KiB. Inspect `learning_get` for outcome provenance, pinned versions,
applicability, sample counts and evaluations. Retrieval cannot change the
approved scope, checks, model/provider, permissions or authored skill instructions.

At most one background learning assignment consumes the approved goal assignment
budget, with10minutes/6coordinator model requests. Native maintenance uses
`native_text_start` under a permitted learning task, `learning_propose`, protected
`learning_evaluate`, then an explicit procedure decision (`learning_promote`,
`learning_quarantine` or `learning_rollback`) and `native_text_finish`. Invalid
proposals and the one allowed correction are still spent. `learning_correct`
creates a separately evaluated candidate; `learning_archive` retains evidence.
Discover required fields; do not fabricate evaluator inputs.

Existing `edit_batch` and narrowly applicable JavaScript `backoff_zero` tests are
`protected_replay`, not evidence of general self-improvement. backoff_zero requires
reviewed zero/overflow failure evidence and checked integration of its correction.
Reflection alone proves no gain. No lesson can modify executable authority,
credentials, runtime settings, trusted checks or core code.
