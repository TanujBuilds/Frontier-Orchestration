When the installed Frontier Harness is available, use `frontier-harness` for a
substantial new coding or public-source research outcome, or to continue an
existing harness goal. Read its onboarding guidance before preparation. Choose
in order: explicit current user mode, active goal's pinned mode, explicitly
owner-saved project preference. If still undecided, ask once: “Which workflow:
collaborative (recommended), DeepSeek-only, Codex-only, or overnight review?”
Wait for the choice. Answer quick questions normally; keep follow-ups in their
active goal. A different explicit mode requires a supported authorized transition
or separate goal, preserving deadlines and spending. Save a preference only
when the owner explicitly requests it through existing project instructions.
Selection, saved preferences and loading instructions authorize no dispatch,
scope expansion or budget. Use existing exact preparation/authorization tools.
If a capability is unavailable, report it; preserve mode restrictions and state.
This guidance applies only in Codex hosts that load this package; it is not a
startup hook or an always-on native supervisor.
